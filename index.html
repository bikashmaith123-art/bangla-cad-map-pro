নির্বাচিত Raster Map-এর অবস্থান ও মাপ নির্দিষ্ট করে বসান। একাধিক Map-এর মধ্যে একই অবস্থান/মাপ মিলিয়েও সাজাতে পারবেন।
প্রথমে Drawing Board-এ একটি Raster Map নির্বাচন করুন।
Auto Trace / Raster-এর দাগ ধরে স্বয়ংক্রিয় লাইন তৈরি
প্রথমে Raster Map নির্বাচন করুন। Auto Trace চালু করে ছবির কালো/গাঢ় দাগের ওপর ক্লিক করুন। সংযুক্ত গাঢ় পিক্সেল থেকে কেন্দ্রীয় Polyline তৈরি হবে।
Raster নির্বাচন করে Auto Trace চালু করুন। গাঢ় দাগের ওপর ক্লিক করুন।
Boundary / Polyline Vertex Editing
Boundary বা Polyline নির্বাচন করুন। মাঝের ছোট হ্যান্ডেলে ট্যাপ করে নতুন Vertex যোগ করুন; বড় হ্যান্ডেল টেনে অবস্থান বদলান।
একটি Boundary বা Polyline নির্বাচন করুন।
Polyline শেষ করতে “Polyline শেষ” চাপুন। Polygon টুলে বন্ধ সীমানা তৈরি হয়। Select অবস্থায় রেখার প্রান্ত/Vertex ধরে টানলে শুধু সেই পয়েন্ট বদলাবে; রেখার মাঝখান ধরে টানলে পুরো অবজেক্ট সরবে। স্কেল ক্যালিব্রেশনের জন্য পরিচিত দৈর্ঘ্যের একটি Line/Polyline আগে নির্বাচন করুন। ম্যাপ/ছবি যোগ করে তার opacity, অবস্থান ও আকার নিয়ন্ত্রণ করা যাবে।
টুল: Select / Move। Select দিয়ে অবজেক্ট টাচ করে সরান। Polyline-এ একের পর এক টাচ করুন, শেষে “Polyline শেষ” চাপুন।

গুরুত্বপূর্ণ: Browser-এর স্থানীয় Snapshot একই ডিভাইস/Browser-এর জন্য। Browser data মুছে গেলে বা ডিভাইস নষ্ট হলে এটি হারাতে পারে। তাই নিয়মিত Backup ডাউনলোড করে আলাদা জায়গায় রাখুন। বড় ম্যাপের মূল ফাইল আলাদাভাবে সংরক্ষণ করুন।

Stage 31 — সর্বডিভাইস Compatibility & Long-Life Foundation

লক্ষ্য: কোনো একটি ফোন, ব্রাউজার, অপারেটিং সিস্টেম বা GNSS ব্র্যান্ডের উপর সফটওয়্যার নির্ভরশীল থাকবে না। মূল CAD/Project কাজ অফলাইনেও চলবে; ডিভাইস-নির্ভর সংযোগ না চললে বিকল্প Import/Export পথ থাকবে।

পরীক্ষা শুরু হয়নি।
সুবিধা / APIঅবস্থাবিকল্প পথ

সর্বজনীন GNSS Adapter নীতি

  • Generic NMEA-0183 হলো মূল ডেটা-ফরম্যাট; GNSS ব্র্যান্ড বদলালেও একই CAD/Survey core ব্যবহার করার নকশা।
  • USB/Serial, Bluetooth LE, Android GPS ও Wi-Fi relay—প্রতিটি আলাদা adapter; কোনো API না থাকলে সেটিকে ব্যর্থতা হিসেবে নয়, ঐ ডিভাইসে অনুপলব্ধ সংযোগ-পথ হিসেবে দেখানো হবে।
  • Hardware না থাকলেও NMEA Log Import এবং স্পষ্টভাবে চিহ্নিত Demo দিয়ে সফটওয়্যার পরীক্ষা করা যাবে। Demo coordinate বাস্তব জরিপে ব্যবহারযোগ্য নয়।
  • Project JSON, CSV, KML এবং অন্যান্য Export/Import হলো ডিভাইস বদলের বহনযোগ্য পথ। Local backup একই ডিভাইসের browser storage-এ সীমাবদ্ধ—আলাদা backup ফাইল রাখুন।
Profile-এ কোনো পাসওয়ার্ড বা NTRIP গোপন তথ্য রাখা হয় না।

বাস্তব সীমা: “সব ডিভাইসে” একই hardware connection নিশ্চিত করা যায় না—Android/iOS/Windows, browser, USB driver, Bluetooth profile ও GNSS receiver অনুযায়ী API আলাদা। এই Stage একটি compatibility-aware fallback ভিত্তি তৈরি করে; প্রতিটি adapter-এর বাস্তব hardware পরীক্ষা আলাদা প্রয়োজন।

Stage 33 — Cross-Platform Architecture & Project Portability

মূল নীতি: CAD/Survey-এর মূল Project Data এক থাকবে; Android, Windows, macOS এবং Apple iPad/iPhone-এ ডিভাইস-নির্ভর কাজ আলাদা Adapter বা উপযোগী Browser/Native Shell দিয়ে চলবে। এই ধাপ Portable Project Package ও Compatibility Readiness-এর ভিত্তি যোগ করে; এটি নিজে থেকে Native App বা Cloud Sync তৈরি করে না।

একটি Project Format

Project JSON-এ format version, metadata ও data validation যুক্ত করে ডিভাইস বদলের পথ।

Platform Adapter

GPS, USB/Serial, Bluetooth, ফাইল ও নেটওয়ার্ক সংযোগ আলাদা স্তরে থাকবে; CAD core এগুলোর উপর নির্ভর করবে না।

Offline-first

স্থানীয় Drawing, হিসাব ও Project কাজ ইন্টারনেট বা GNSS hardware ছাড়াও চলার নকশা। Online map/relay-এর জন্য সংযোগ লাগবে।

Future Native Shell

macOS/iOS-এর জন্য Swift + WKWebView, Windows-এর জন্য উপযুক্ত Desktop Shell, Android-এর জন্য Web/PWA বা Native Wrapper—পরবর্তী পৃথক নির্মাণধাপ।

প্রস্তুত। আগে Readiness পরীক্ষা চালাতে পারেন অথবা Portable Package তৈরি করতে পারেন।

Cross-platform লক্ষ্য

প্ল্যাটফর্মপ্রধান ব্যবহারযে বিষয় আলাদাভাবে যাচাই করতে হবে
Android Phone/TabletTouch CAD, GPS, file import/exportBrowser version, permission, USB/Bluetooth adapter
Windows Laptop/DesktopMouse/keyboard CAD, বড় project, USB GNSSBrowser/driver, serial permission, storage
macOS MacBook/iMacSafari/Chrome/Edge CAD, file workflowsSafari hardware API সীমা; প্রয়োজনে signed native adapter
iPad/iPhoneTouch workflow, project review, field dataiOS file access, background limits, native GNSS bridge

সতর্কতা: Portable Package-এ Project Data থাকবে, কিন্তু বাইরের Raster/Map image যদি আলাদা ফাইল হিসেবে থাকে, সেই মূল image-ও আলাদাভাবে কপি করতে হবে। NTRIP password, access token বা ব্যক্তিগত credentials কখনো package-এ যোগ করা হবে না। Cloud sync, conflict merge, Native installers এবং প্রতিটি GNSS adapter-এর বাস্তব পরীক্ষা পরবর্তী কাজ।

Stage 34 — Project Version Management & Safe Migration

লক্ষ্য: সফটওয়্যারের ভবিষ্যৎ সংস্করণে পুরোনো Project খোলার পথ রাখা। কোনো অজানা/নতুন format জোর করে পুরোনো সংস্করণে খোলা হবে না; মূল ফাইল না বদলে আগে যাচাই ও নিরাপদ কপি তৈরি হবে।

Format শনাক্তকরণ

Project-এর format identifier, package version ও প্রয়োজনীয় data section পরীক্ষা।

Conservative Migration

শুধু নিরাপদ, additive default যোগ; অজানা field ও মূল geometry অক্ষত রাখা।

Backup First

Import-এর আগে বর্তমান Project-এর backup তৈরি করার স্মরণ করানো।

Forward Compatibility

ভবিষ্যতের অচেনা format শনাক্ত হলে পরিবর্তন না করে Import বন্ধ রাখা।

প্রস্তুত। Project format পরীক্ষা করতে পারেন।

গুরুত্বপূর্ণ: এই ধাপটি version identification ও conservative migration framework যোগ করে; সব অতীত/ভবিষ্যৎ format-এর জন্য পূর্ণ migration map এখনো তৈরি হয়নি। কোনো field-এর অর্থ নিশ্চিত না হলে সেটি স্বয়ংক্রিয়ভাবে রূপান্তর করা হবে না। Project-এর বাইরের Raster/Map image আলাদা ফাইল হলে সেটিও আলাদাভাবে ব্যাকআপ রাখতে হবে।

Stage 35 — Large Drawing Performance & Device Resilience

লক্ষ্য: বড় Drawing বা অনেকগুলো CAD object থাকলেও অপ্রয়োজনীয় বারবার redraw কমানো, ডিভাইসের ক্ষমতা অনুযায়ী সতর্কতা দেওয়া এবং কম ক্ষমতার ডিভাইসেও মূল কাজ চালু রাখা।

Smart Redraw

একই মুহূর্তে একাধিক redraw request এলে একটি animation frame-এ একত্র করা।

Project Load Check

Drawing, Map, GPS point এবং Project JSON-এর আনুমানিক আকার পরীক্ষা।

Device-aware Advice

বড় Project হলে আলাদা backup, image optimization ও ছোট অংশে কাজের পরামর্শ।

Graceful Degradation

Performance helper ব্যর্থ হলেও আগের Drawing renderer-এ ফিরে যাওয়ার ব্যবস্থা।

প্রস্তুত। Performance পরীক্ষা চালাতে পারেন।

সীমাবদ্ধতা: এটি renderer request coalescing ও diagnostic ভিত্তি; পূর্ণ spatial indexing, tiled rendering, worker-based geometry engine বা hardware benchmark নয়। বড় Raster image ও browser memory-এর সীমা ডিভাইসভেদে আলাদা। মূল Project data স্বয়ংক্রিয়ভাবে সংকুচিত বা পরিবর্তন করা হয় না।

Stage 36 — নিরাপদ Multi-Device Project Transfer

এক ডিভাইস থেকে অন্য ডিভাইসে Project নেওয়ার জন্য যাচাইকৃত Transfer Package তৈরি করুন। এটি এখন File-based transfer; সার্ভার বা স্বয়ংক্রিয় Cloud Sync নয়।

প্রস্তুত। প্রথমে Export করে অন্য ডিভাইসে ফাইলটি পাঠাতে পারেন।

নিরাপত্তা: এই ব্যবস্থা বিদ্যমান Project-কে স্বয়ংক্রিয়ভাবে overwrite করে না। একই Project থাকলে আলাদা Copy হিসেবে সংরক্ষণ করে; পরে ব্যবহারকারী নিজে Library থেকে খুলবেন। Package-এ Project data থাকতে পারে—বিশ্বস্ত ব্যক্তির সঙ্গেই শেয়ার করুন। Map-এর মূল ছবি/রaster file আলাদাভাবে পাঠাতে হতে পারে।

Stage 37 — Data Integrity, Compatibility Audit ও নিরাপদ Recovery

এই পরীক্ষা বর্তমান Project বা পুরোনো ফিচার পরিবর্তন করে না। এটি প্রয়োজনীয় ফাংশন, Project data, Storage এবং Browser সুবিধা পরীক্ষা করে রিপোর্ট তৈরি করে।

প্রস্তুত। পরীক্ষা চালালে কোনো Drawing বা Project পরিবর্তন করা হবে না।
পরীক্ষাঅবস্থাবিস্তারিত / করণীয়
এখনও পরীক্ষা চালানো হয়নি।

সতর্কতা: এই Audit স্বয়ংক্রিয়ভাবে সব UI বোতাম, বাহ্যিক Map service, GNSS hardware, Browser permission বা সব Export ফাইলের বাস্তব ফল পরীক্ষা করতে পারে না। চূড়ান্ত নিশ্চয়তার জন্য বাস্তব ডিভাইসে ব্যবহারিক পরীক্ষা প্রয়োজন। জরুরি Backup আলাদা জায়গায় রাখুন।

Stage 38 — Recovery Assurance, Regression Guard ও Data Protection

এই অংশটি মূল Drawing বা Project পরিবর্তন না করে নিরাপদ Checkpoint, Recovery তালিকা ও Runtime Error Report তৈরি করে। কোনো Restore করার আগে বর্তমান Project-এর আলাদা Backup রাখুন।

প্রস্তুত। প্রথমে একটি Checkpoint তৈরি করে আলাদা জায়গায় Backup রাখুন।

পরীক্ষার ফলাফল

এখনও পরীক্ষা চালানো হয়নি।

গুরুত্বপূর্ণ: Browser-এর Checkpoint কেবল একই Browser/Device-এ থাকে; Browser data মুছে গেলে হারাতে পারে। ডাউনলোড করা JSON Backup অন্য Drive/Device-এ রাখুন। Checkpoint তৈরি করা মানেই সব Map-এর আসল ছবি/টাইলস সংরক্ষিত হয়েছে এমন নয়; মূল Map/Image ফাইল আলাদাভাবে রাখুন। এই ধাপ বাস্তব GNSS, Cloud Sync বা সব UI workflow-এর end-to-end পরীক্ষা নয়।

Stage 39 — Security Guard & Safe Project Protection

Project Import, ফাইলের গঠন, ব্রাউজার নিরাপত্তা ও সম্ভাব্য ঝুঁকির প্রাথমিক পরীক্ষা। এটি Antivirus-এর বিকল্প নয়।

Security Check এখনও চালানো হয়নি।
  • শুধু পরিচিত উৎসের সফটওয়্যার ও Project File ব্যবহার করুন।
  • অজানা HTML/EXE/APK/DMG ফাইল Project Import-এ দেবেন না।
  • গুরুত্বপূর্ণ Project-এর আলাদা Offline Backup রাখুন।
  • সফটওয়্যার আপডেট প্রকাশের আগে Code Signing, Malware Scan ও Release Verification প্রয়োজন।

Stage 40 — Backup Integrity & File Safety Guard

Import করার আগে JSON ফাইলের আকার, গঠন, সন্দেহজনক Property এবং SHA-256 Hash পরীক্ষা করুন। এটি Antivirus বা পূর্ণ Malware Scanner নয়; কোনো ফাইলকে শতভাগ নিরাপদ বলে সার্টিফাই করে না।

কোনো ফাইল পরীক্ষা করা হয়নি।










 
Stage 41 — নিরাপত্তা ও পারফরম্যান্স স্ক্যানার

 
এই স্ক্যানার Land Survey CAD Pro-এর নির্বাচিত প্রজেক্ট/ফাইল এবং ব্রাউজারে দৃশ্যমান পারফরম্যান্স পরীক্ষা করবে। এটি পুরো Android/Windows ডিভাইসের অ্যান্টিভাইরাস নয়।

এখনও কোনো স্ক্যান চালানো হয়নি।

 সীমাবদ্ধতা: ব্রাউজার অন্য অ্যাপ/সিস্টেম ফাইল, RAM-এর সব প্রক্রিয়া বা সম্পূর্ণ ডিভাইস স্ক্যান করতে পারে না। সন্দেহজনক টেক্সট পাওয়া মানেই ভাইরাস প্রমাণ নয়। অজানা ফাইল খুলবেন না; গুরুত্বপূর্ণ ডেটার ব্যাকআপ রাখুন।









 
Stage 42 — User Login & Permission Security
